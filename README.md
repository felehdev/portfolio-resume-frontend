# Commit Message Types

When committing changes, use one of the following types to categorize your commit:

### Types

- **`build`**

  - _Description_: Changes that affect the build system or external dependencies.
  - _Examples_: gulp, broccoli, npm.

- **`docs`**

  - _Description_: Documentation-only changes.
  - _Examples_: Updating README, API docs, or other documentation files.

- **`feat`**

  - _Description_: A new feature.
  - _Examples_: Adding a new module, API endpoint, or user interface component.

- **`fix`**

  - _Description_: A bug fix.
  - _Examples_: Correcting a typo in the code, fixing a broken feature, or resolving an error.

- **`perf`**

  - _Description_: A code change that improves performance.
  - _Examples_: Optimizing an algorithm, reducing load time, or improving memory usage.

- **`refactor`**

  - _Description_: A code change that neither fixes a bug nor adds a feature.
  - _Examples_: Simplifying logic, reorganizing code, or improving code readability.

- **`style`**

  - _Description_: Changes that do not affect the meaning of the code.
  - _Examples_: White-space, formatting, missing semi-colons, or renaming variables for clarity.

- **`test`**
  - _Description_: Adding missing tests or correcting existing tests.
  - _Examples_: Writing unit tests, fixing broken test cases, or adding integration tests.

### Example Commit Messages

- `feat: add user authentication`
- `fix: resolve issue with login redirect`
- `docs: update README with installation instructions`
- `perf: improve database query efficiency`
- `style: reformat code for better readability`
